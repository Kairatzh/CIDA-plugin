# Kairos · Этап 0 — CIDA-Loop

Решающий эксперимент перед любыми большими моделями: **даёт ли латентное обсуждение агентов (CIDA)
что-то сверх простого рекуррентного цикла?**

## Что внутри
- `model.py` — рекуррентное ядро в стиле TRM ([arXiv:2510.04871](https://arxiv.org/abs/2510.04871)) в двух вариантах:
  - `plain`: `z ← net(x + y + z)`, `y ← net(y + z)`;
  - `cida`: `z` — это K агентов **по каждому токену** (а не один пулинговый вектор, как в старой CIDA);
    после каждого шага агенты обмениваются сообщениями (внимание K×K, смещённое к разногласию),
    ответ строится консенсусом, взвешенным уверенностью, а согласие агентов служит мерой уверенности.
  Сеть `net` общая, поэтому CIDA добавляет около 6% параметров (1.23M против 1.17M при d=256).
- `sudoku.py` — Sudoku-Extreme (HF `sapientinc/sudoku-extreme`) или локальный генератор с единственным решением, плюс аугментации симметриями.
- `train.py` — глубокая супервизия, обученная остановка, EMA весов, bf16, `--compile`. Оценка проводится только на отложенных головоломках.
- `metrics.py` — ECE и AUROC (насколько уверенность отличает верные ответы от неверных).
- `report.py` — сводная таблица `среднее ± std` по зёрнам.

## Запуск
Colab: `notebooks/Kairos_Stage0_CIDA_Loop.ipynb`. Локально:
```bash
python -m kairos_loop.train --variant cida --out runs/cida_s0
python -m kairos_loop.train --variant plain --out runs/plain_s0
python -m kairos_loop.train --variant plain --n-latent 24 --out runs/plain_compute_s0
python -m kairos_loop.report runs/*/result.json
```

## Честное сравнение
CIDA с K=4 тратит на латентные шаги в 4 раза больше вычислений. Поэтому обязательны две базовые линии:
`plain` (те же параметры) и `plain_compute` (`--n-latent 24`, те же FLOPs).
**CIDA засчитывается, только если обгоняет обе на ≥3 зёрнах.** Отрицательный результат тоже результат.

## Про Triton
`--compile` включает `torch.compile`: Inductor сам генерирует фьюзнутые Triton-ядра для цикла.
Внутри forward нет `.item()` и синхронизаций CPU↔GPU, так что граф компилируется целиком.
Своё Triton-ядро для шага обсуждения имеет смысл писать только после профилирования, если связь агентов окажется узким местом.
