# 🚀 План реализации: CIDA SRE Demo (72 часа)

Этот документ описывает фазы разработки, архитектуру каталогов и структуру модулей для демонстрации автономного управления IT-инфраструктурой агентом CIDA SRE.

---

## 📂 Структура папки `cida_sre_demo/`

Все файлы проекта размещаются в новой папке `cida_sre_demo/` в корне репозитория:

```
cida_sre_demo/
│
├── README.md                   # Общее описание проекта и фаз
├── implementation_plan.md      # Этот файл (план разработки)
├── simulator.py                # Симулятор инфраструктуры (40+ сервисов, метрики, базы, инструменты)
├── scenarios.py                # Реализация 20 сценариев (атаки, баги, каскадные сбои)
├── agent_swarm.py              # Инициализация CidaSwarm и агентов (Incident, Security, Optimization, Report)
├── run_demo.py                 # Сценарий автоматического запуска демонстрации
└── debug_runner.ipynb          # Jupyter-ноутбук для поэтапного запуска, визуализации и отладки
```

---

## ⏱️ Фазы разработки

### 🟢 Фаза 1: Симулятор инфраструктуры (`simulator.py`)
- **Задача:** Создать виртуальное окружение, моделирующее 40+ микросервисов и баз данных (Kubernetes pods, Postgres, Redis, Kafka, Nginx, S3).
- **Инструменты:** Реализация 40 mock-функций для чтения метрик, изменения стейта (scale, restart, block IP) и получения логов.
- **Особенности:** Должен корректно симулировать латентность ответов, ошибки сети, падение баз и блокировки.

### 🟡 Фаза 2: Сценарии инцидентов и атак (`scenarios.py`)
- **Задача:** Запрограммировать 20 сценариев (от OOM до APT и Perfect Storm).
- **Логика сценария:** Каждая атака/баг изменяет внутреннее состояние симулятора (например, выставляет CPU=99% или отключает реплики).
- **Критерии успеха:** Определение чётких условий, при которых инцидент считается решённым (например, баланс ресурсов пришёл в норму, вредоносный IP заблокирован).

### 🟠 Фаза 3: Оркестрация Swarm и Агентов (`agent_swarm.py`)
- **Задача:** Интеграция с `cida-plugin` для создания мультиагентного роя (CidaSwarm) с разделяемой `LatentMemory`.
- **Роли агентов:**
  - `IncidentAgent`: фокус на восстановлении работоспособности (Kubernetes, DB).
  - `SecurityAgent`: блокировка атак, сканирование логов, WAF.
  - `OptimizationAgent`: автоскейлинг, балансировка трафика.
  - `ReportAgent`: сбор метрик, ведение логов инцидентов, генерация финального отчёта.

### 🔴 Фаза 4: Запуск и Ноутбук-Отладчик (`run_demo.py` & `debug_runner.ipynb`)
- **Задача:** Создать единую точку сборки. Ноутбук должен позволять:
  - Шаг за шагом запускать каждый сценарий по отдельности.
  - Логировать внутренние дебаты CIDA (Skeptic vs Prosecutor).
  - Сравнивать поведение базового агента (Qwen без CIDA) и CIDA-агента.
  - Отрисовывать красивые графики (VRAM, потребление токенов, CPU, время восстановления).
