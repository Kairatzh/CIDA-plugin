# Kairos-KZ: план от модели к продукту

Цель: за 6–8 недель на Colab Pro выпустить первую модель Kairos — небольшую казахско-русскую модель,
которая умеет рассуждать и **честно говорит «не уверена»**, а не выдумывает. Последнее — вклад CIDA.

## 1. Продукт и первый сценарий

Не «ещё один чат на казахском» — с этим уже есть KazLLM (ISSAI), Sherkala, Alem.
Нужна узкая ниша, где можно автоматически проверить ответ и где ошибка дорого стоит.

**Первый сценарий: репетитор по математике и логике для ЕНТ на казахском.**
- Ответы проверяемы (число, вариант ответа) → можно учить через GRPO без учителя-человека.
- Понятный рынок: школьники, репетиторские центры, онлайн-школы Казахстана.
- CIDA-слой отвечает: «здесь я не уверена, проверь с учителем» — это продаваемое свойство.

Следующие сценарии (после v1): справки по госуслугам/законам (RAG + отказ при неуверенности),
корпоративный помощник для банков и телеком-компаний.

## 2. Стек и ускорение обучения

| Что | Чем | Зачем |
|---|---|---|
| GPU | Colab Pro: A100 40 GB (или L4) | bf16, flash attention |
| Дообучение | **Unsloth** (LoRA/QLoRA) + TRL | в ~2 раза быстрее и экономнее по памяти, чем чистый HF |
| GRPO | TRL `GRPOTrainer` через Unsloth + vLLM | генерация в GRPO — самое медленное место, vLLM ускоряет её в разы |
| Длинные примеры | packing последовательностей, gradient checkpointing | меньше простоя GPU |
| Сохранение | Google Drive + приватный репозиторий HF Hub | Colab отключается, чекпоинты не теряются |

Свои Triton-ядра сейчас не пишем: Unsloth уже содержит готовые. Это вернётся позже, когда будет своя архитектура.

**Базовая модель:** самая свежая маленькая модель Qwen под Apache 2.0 (на момент старта — Qwen3 1.7B/4B,
проверить, не вышла ли новее). Начинаем с 1.7B: быстрые итерации. 4B — финальный кандидат.
Только лицензии Apache/MIT: иначе продавать будет нельзя.

## 3. Данные

**3.1. Готовое на Hugging Face (основной объём, бесплатно)**
- Рассуждения по математике: OpenR1-Math-220k, OpenThoughts, NuminaMath — проверить лицензию каждого.
- Казахские инструкции: `AmanMussa/kazakh-instruction-v1` (MIT), датасет по госуправлению и культуре
  из arXiv 2502.13647, параллельный корпус KazParC — лицензии сверить до использования.
- Оценка: KazMMLU (если доступен), отложенная часть наших задач ЕНТ.

**3.2. Дистилляция через OpenRouter (точечно, не для объёма)**
- Бесплатные модели (`:free`): ~20 запросов/мин, 50 в день без покупок, 1000 в день после покупки
  $10 кредитов (по сторонним обзорам — свериться с `GET /api/v1/key`). 1000/день ≈ 30k примеров в месяц:
  хватит на казахскую часть, но не на 200k рассуждений.
- **Учителя — только открытые модели с разрешающей лицензией** (DeepSeek — MIT, Qwen — Apache).
  Условия OpenAI, Anthropic и Google запрещают обучать конкурирующие модели на их ответах:
  такой датасет сделает продукт юридически непродаваемым.
- Задача учителя: перевести и переписать рассуждения из 3.1 на казахский, сгенерировать задачи в стиле ЕНТ.
- Всё, что сгенерировано, проходит фильтр: ответ сверяется с эталоном, казахский текст проверяется
  на долю казахских букв (ә ғ қ ң ө ұ ү һ і), дубликаты удаляются.

## 4. Этапы обучения

**Этап 1. SFT-дистилляция (≈1 неделя).**
LoRA на готовых рассуждениях + казахском наборе. Сначала 1.7B, потом 4B.
Итог: модель рассуждает пошагово на казахском и русском.

**Этап 2. GRPO с проверяемой наградой (≈1–2 недели).**
Важно: GRPO не учится на ответах учителя. Модель сама генерирует несколько ответов на задачу,
функция награды их оценивает, и модель усиливает лучшие. Учитель здесь не нужен — нужны задачи с эталоном.
Награды:
- правильный итоговый ответ (главная);
- формат (рассуждение, затем ответ в заданном виде);
- язык: ответ на казахском, если вопрос на казахском;
- штраф за слишком длинные рассуждения.
LLM-судья в качестве награды возможен, но через бесплатный OpenRouter слишком медленный — откладываем.

**Этап 3. CIDA-слой уверенности (≈1 неделя).**
Модель отвечает K раз (разная температура или разные «роли» в промпте) → CIDA считает согласие →
конформная калибровка выбирает порог → ниже порога модель отвечает «не уверена».
Метрика продукта: кривая «риск–покрытие» (насколько меньше ошибок при отказе от X% вопросов),
сравнение с простым голосованием большинства и с вероятностью модели. Если CIDA не лучше
голосования — честно используем голосование и не заявляем CIDA как преимущество.

**Этап 4. Оценка и релиз (≈1 неделя).**
Отложенные задачи ЕНТ, KazMMLU, сравнение с базовой Qwen, KazLLM и Sherkala того же размера.
Публикация весов на HF, демо в Telegram-боте, API для партнёров.

## 6. Риски

- **Лицензии данных** — главный риск для продажи. Каждый датасет и каждый учитель вносятся в таблицу лицензий.
- **Качество казахского у учителей.** Открытые модели пишут на казахском хуже, чем на русском →
  выборочная ручная проверка 100–200 примеров носителем языка.
- **Утечка тестовых задач** в обучение → дедупликация по тексту задачи между train и test.
- **Бесплатные модели OpenRouter** пропадают без предупреждения → список запасных моделей в запросе.

## 7. Что делаем первым

1. Таблица лицензий + скрипт загрузки и фильтрации данных (`kairos_llm/data/`).
2. Ноутбук SFT на Unsloth для 1.7B с сохранением на Drive.
3. Скрипт дистилляции через OpenRouter с лимитами, повторами и фильтрами.
4. Ноутбук GRPO с наградами за ответ, формат и язык.
5. CIDA-слой и оценка «риск–покрытие».

Эксперимент на судоку (Этап 0) не выбрасываем: он остаётся научной проверкой самой идеи CIDA-Loop
и может идти в фоне, когда GPU свободен.
