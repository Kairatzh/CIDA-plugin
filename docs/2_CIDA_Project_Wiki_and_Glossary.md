## 📐 Часть 3: Глоссарий — Все Термины Проекта

> Алфавитный порядок. Используйте `Ctrl+F` для поиска нужного термина.

---

### A

**Agentic Resilience (Агентная Устойчивость)**
Способность `LatentAgent` автономно справляться с ошибками внешних API и инструментов. Когда библиотека Python падает с краш-ошибкой, CIDA перехватывает её, активирует Rollback, затем самостоятельно переключается на прямые HTTP-запросы к API, минуя сломанную библиотеку.

**Aleatoric Uncertainty (Шумовая неопределённость)**
Тип неопределённости, исходящий из качества входных данных (плохой рентгеновский снимок, зашумлённый текст). CIDA умеет **отдельно** измерять этот тип неопределённости от Epistemic Uncertainty.

---

### B

**BIG-Bench Hard (BBH)**
Набор из 23 сложнейших логических задач, разработанный Google. Является одним из наших ключевых бенчмарков. CIDA показывает **10x рост** точности на BBH (с 4.4% до 44%) относительно базового Qwen.

**backbone** (базовая модель)
Основная языковая модель (LLM), поверх которой работает CIDA. Текущая производственная версия использует **Qwen2.5-7B-Instruct**. CIDA полностью агностична к backbone — можно подключить любую HF-модель.

---

### C

**CIDA** (Cognitive Interactive Deliberation Agents)
Главная технология проекта. Плагин-слой, добавляющий "Систему 2 мышления" к любой языковой или визуальной модели. Работает через внутренние дебаты 4 виртуальных агентов в латентном пространстве.

**CIDAPlugin**
Главный Python-класс ядра системы. Находится в `cida_plugin/core.py`. Это нейронная сеть, которая принимает скрытое состояние (hidden state) от LLM и прогоняет его через мульти-агентные дебаты.

**CidaSwarm**
Класс в `cida_plugin/inference/swarm.py`. Оркестрирует команду из нескольких `LatentAgent`-ов. Поддерживает три режима:
- `auto_route` — автоматически направляет задачу нужному агенту
- `pipeline` — агенты работают цепочкой
- `fan_out_fan_in` — агенты работают параллельно, потом их выходы объединяются

**compile_from_text()**
Ключевой метод класса `LatentPrompt`. Принимает длинный текстовый промпт (тысячи слов), разбивает его на логические блоки и прогоняет каждый через LLM, извлекая скрытые состояния. Результат — список векторов (Latent Concepts).

**Cross-Attention**
Механизм в трансформерах, где запрос (query) ищет наиболее релевантные ключи в памяти. В контексте CIDA — это то, как агент при обработке пользовательского запроса "ищет" нужные концепции в Latent Memory.

---

### D

**d_hidden**
Внутренняя размерность скрытого слоя CIDA-агентов. По умолчанию 512. Не совпадает с `d_llm` (размерностью LLM).

**d_llm**
Размерность скрытых состояний (hidden states) базовой LLM. Для Qwen2.5-7B это **3584**. CIDA использует проектор для перевода между `d_hidden` и `d_llm`.

**decay_weights**
Параметр в `LatentMemory`. Контролирует, как долго вектор живёт в памяти. Неиспользуемые воспоминания теряют 10% каждый шаг. Системные латентные промпты получают `decay_weight = 999.0` — практическое бессмертие.

**Deliberation Loop (Петля Дебатов)**
Центральный цикл работы CIDA. Агенты обмениваются аргументами `R` раундов (по умолчанию 3-5). После каждого раунда их убеждения (beliefs) обновляются. После последнего раунда — достигается Консенсус.

---

### E

**ECE** (Expected Calibration Error)
Метрика калибровки модели. Измеряет, насколько уверенность модели соответствует реальной точности. Для медицинского применения критически важен низкий ECE. CIDA достигает ECE = **0.034** (против 0.082 у baseline).

**Epistemic Uncertainty (Модельная неопределённость)**
Тип неопределённости, исходящий из ограниченности знаний модели (редкое заболевание, которое модель не видела в обучении). CIDA измеряет его отдельно от Aleatoric Uncertainty.

---

### F

**Fast Path (Быстрый путь)**
Механизм раннего выхода в `LatentReasoner`. Если дисперсия скрытых состояний агентов мала (задача тривиальная), CIDA **пропускает** все раунды дебатов и отвечает напрямую. Это ускоряет инференс на простых запросах в 3 раза.

**Fidelity Loss (Потеря точности)**
Известное ограничение латентной памяти. Векторы идеально передают концепции и логику ("намерение взломать замок"), но не могут надёжно хранить точные строки ("пароль: `A4f!9#Bz`"). Решается через Hybrid Latent Architecture.

---

### G

**GSM8K**
Набор из 8500 школьных математических задач. Один из стандартных бенчмарков. CIDA улучшает точность с **8% до 42%** на этом датасете.

**Gradient Checkpointing**
Техника оптимизации памяти GPU при обучении. Вместо хранения всех промежуточных активаций, они пересчитываются по мере необходимости. Позволяет обучать CIDA на бесплатных T4 GPU в Google Colab без Out-of-Memory ошибок.

---

### H

**h_last** (Last Token Hidden State)
Скрытое состояние последнего токена входного промпта в базовой LLM. Это вход для CIDA — сжатое представление всего смысла запроса в одном векторе.

**Halting Predictor**
Компонент CIDA, который предсказывает, стоит ли продолжать дебаты. Если агенты достигли консенсуса раньше максимального числа раундов, Halting Predictor останавливает цикл.

**Hybrid Latent Architecture**
Архитектура для мультиагентных систем, решающая проблему Fidelity Loss. Логика передаётся через Latent Memory (быстро, дёшево), а точные дискретные данные (IP, хэши) хранятся в `shared_artifacts` (JSON-словарь в системном промпте).

---

### K

**KairosOrchestrator**
Главный высокоуровневый класс в `cida_plugin/orchestrator.py`. Загружает и соединяет два компонента: frozen LLM backbone + обученный CIDAPlugin. Является единственной точкой входа для работы с полной системой.

**Kairos OS**
Медицинское применение CIDA. Полный пайплайн: визуальный энкодер (BiomedCLIP/EfficientNet) → CIDA → LLM → клинический отчёт. Достиг ROC-AUC > 0.90 на Stanford CheXpert.

**KDD** (Kairos Dynamic Deliberation)
Механизм Rollback. Синоним Latent Rollback, исторически использовался в контексте Kairos OS.

---

### L

**Latent Concept (Латентная концепция)**
Один вектор, извлечённый методом `compile_from_text()` из одного смыслового блока текстового промпта. Набор таких векторов образует Multi-Vector Latent Prompt.

**Latent Engineering (Латентная Инженерия)**
Новая парадигма программирования ИИ-систем. Вместо написания текстовых промптов → компиляция текста в векторы и работа напрямую с ними. Реализована в `cida_plugin/inference/latent_engineering.py`.

**Latent Firewall (Латентный Брандмауэр)**
Защитный механизм `LatentAgent`. Вектор "запрещённого поведения" инъецируется в память с экстремально высоким весом. При попытке агента сгенерировать нежелательный план, сходство с вектором-блокировщиком велико и агент меняет курс.

**Latent Fidelity Loss** — см. Fidelity Loss

**LatentMemory**
Класс в `cida_plugin/inference/latent_memory.py`. L2-нормализованная косинусная векторная база данных. Хранит скрытые состояния (воспоминания). Использует температурное масштабирование 10.0 для предотвращения насыщения softmax. Поддерживает decay векторов.

**LatentPrompt**
Класс в `cida_plugin/inference/latent_engineering.py`. Контейнер для одного или нескольких Latent Concepts. Умеет сохраняться на диск (`.pt` файл), загружаться с диска и загружаться напрямую с Hugging Face Hub.

**Latent Rollback**
Механизм самокоррекции CIDA. Если Скептик и Прокурор расходятся во мнениях сильнее порога 0.20, система перемешивает латентное состояние и запускает дополнительные раунды дебатов. Аналог судебного доследования.

**LatentReasoner**
Класс в `cida_plugin/inference/latent_reasoner.py`. Выполняет `K` раундов "молчаливого мышления" в латентном пространстве перед генерацией текста.

**Liquid Neural ODE**
Математический фреймворк для дебатов, где агентские состояния обновляются не по дискретным шагам, а как непрерывный поток во времени, описываемый обыкновенными дифференциальными уравнениями. Реализован в `cida_plugin/liquid_dynamics.py`.

---

### M

**Multi-Vector Latent Prompt**
Латентный промпт, составленный из нескольких Latent Concepts. Позволяет хранить сложные инструкции, разбитые на логические блоки, для точечного Cross-Attention при поиске нужного правила.

---

### P

**parser_utils.py**
Промышленно прочный парсер инструментов в `cida_plugin/inference/parser_utils.py`. Умеет разбирать вложенные JSON, списки, словари как аргументы инструментов — без краша при наличии запятых внутри.

**Plan Cache (Кэш планов)**
Механизм в `LatentAgent`. Если новый запрос похож на предыдущий (косинусное сходство > 0.96), агент повторно использует уже вычисленный план вместо запуска новых дебатов. Исключение: если предыдущий план завершился ошибкой.

**PlanProjector**
Нейронная сеть, переводящая сжатый вектор консенсуса CIDA в набор "виртуальных токенов" (Virtual Plan Tokens), которые LLM воспринимает как обычные входные данные.

**ProofWriter**
Датасет первого порядка логики, используемый для обучения CIDA v3. 15,000 примеров строгих логических дедукций. Обеспечивает обобщение логики за рамки обучающего распределения (OOD).

---

### R

**ReAct (Reason + Act)**
Архитектурный паттерн работы агента: Думать → Действовать → Наблюдать → Думать снова. `LatentAgent` реализует расширенную версию ReAct с латентным мышлением (бесплатное с точки зрения токенов).

**ROC-AUC**
Метрика качества бинарной классификации. Чем ближе к 1.0 — тем лучше. Клинически значимый порог — > 0.90. CIDA Kairos OS превышает этот порог на датасете Stanford CheXpert.

**Role Prior (Ролевой приор)**
Начальное смещение убеждений агента, определяющее его "роль" в дебатах. Прокурор изначально настроен искать подтверждение, Скептик — опровержение. Это структурное несогласие и запускает продуктивные дебаты.

---

### S

**Shared Artifacts**
В `CidaSwarm` — глобальный JSON-словарь, куда агенты записывают точные дискретные данные (IP-адреса, хэши). Инъецируется в системный промпт следующего агента в цепочке.

**Silent Mode (`silent_mode=True`)**
Режим работы `LatentAgent`, при котором он не генерирует текстовые пояснения своих мыслей. Все рассуждения происходят в латентном пространстве. Минимизирует количество токенов и максимизирует скорость.

**SWA** (Stochastic Weight Averaging)
Техника обучения: веса модели усредняются по нескольким последним эпохам, а не берутся из последней. Стабилизирует распознавание редких патологий в медицинском контексте. Использована в Kairos OS.

---

### T

**Test-Time Training (TTT)**
Механизм в `cida_plugin/ttt.py`. CIDA может адаптировать свои веса прямо во время инференса — без полного переобучения. Используется для быстрой специализации под конкретный домен при первых запросах.

**Tool Exhaustion Circuit Breaker (Автоматический выключатель инструментов)**
Механизм безопасности в `LatentAgent`. Если один и тот же инструмент падает с ошибкой 3 раза подряд, его вектор-идентификатор инъецируется в Latent Firewall, и агент перестаёт им пользоваться. Автоматически разблокируется при успехе.

**TTT** — см. Test-Time Training

---

### V

**Virtual Plan Tokens**
Виртуальные токены, создаваемые PlanProjector из консенсуса CIDA. Они вставляются перед настоящим ответом LLM, "направляя" модель на верный путь ответа, не будучи видимыми в итоговом тексте.

## ⚙️ Часть 4: Минимальный Пример Кода

Для всей команды — три ключевых паттерна использования:

### Паттерн 1: Инициализация системы (с 4-бит квантизацией для Colab)
```python
import torch
from cida_plugin.orchestrator import KairosOrchestrator

orchestrator = KairosOrchestrator(
    backbone_model_name="Qwen/Qwen2.5-7B-Instruct",
    cida_model_path_or_repo="kirtzh/Kairos-7B-CIDA-v1.5",  # Наши обученные веса
    device="cuda",
    torch_dtype=torch.bfloat16,
    load_in_4bit=True  # Обязательно для Colab T4 (14 GB VRAM)
)
```

### Паттерн 2: Создание и сохранение Латентного Промпта
```python
from cida_plugin.inference.latent_engineering import LatentPrompt

# Компилируем текст в векторы (делается один раз!)
my_rules = """
Ты — senior DevOps-инженер. Ты никогда не удаляешь production базы данных.
Перед любым опасным действием ты запрашиваешь подтверждение.
"""
latent = LatentPrompt.compile_from_text(orchestrator, my_rules)
latent.save_local("my_devops_brain.pt")  # Сохраняем на диск
```

### Паттерн 3: Запуск агента с Латентным Промптом
```python
from cida_plugin.inference import LatentAgent, LatentMemory
from cida_plugin.inference.latent_engineering import LatentPrompt

# Загружаем мозг и запускаем агента
brain = LatentPrompt.load_local("my_devops_brain.pt")
agent = LatentAgent(
    wrapper=orchestrator,
    llm=orchestrator.llm,
    tokenizer=orchestrator.tokenizer,
    latent_prompt=brain  # Мозг инъецируется и живёт вечно в памяти
)
result = agent.run("Проверь статус сервера и доложи об ошибках.")
```
